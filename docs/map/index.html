    Special cases

    Real agents don't always follow the happy path. Each of these is a test that runs on every Claude model.

    Claude asks for two tools at once

    The engine can only pause one call. The first pauses; the second gets "one at a time, ask again after this result". Claude asks again in the next step, so nothing is lost.

    A tool fails

    An unknown order makes the lookup fail. The error goes back to Claude as the tool result, so Claude explains instead of guessing. No refund is made.

    The manager says no

    Claude is told the refund was rejected. It does not try again, and no money moves.

    The manager answers in two days

    The wait lives in Temporal, not in a running program. Machines can restart or be replaced while it waits.

    What we found inside the engine

    The Claude engine is closed source, so we tested it until it broke, then worked around each problem. None of these were documented.

    • After one pause, the engine ignored the next pause request.

      Hand the saved result back as a normal message. Our hook always says pause.

    • Rewinding a conversation after a crash broke the paused state.

      A plain resume after a crash, which works even on a different machine.

    • With two tools asked at once, the engine kept one and silently dropped the other.

      The first pauses; the second is told to wait and is asked for again.

    • On every resume, the engine announces the call we just answered again.

      We recognize the repeat and ignore it.

    • A Claude app login cannot renew itself when a paused session resumes.

      A long-lived login token, an API key, or Amazon Bedrock.

    • Opus 5.5 needs a newer engine than the one inside the SDK.

      Point the package at Claude Code 2.1.280 with one setting.
